# Phase 3 gate: requester transcripts (2026-09-24)

The gate, from AOR roadmap/14 §9 Phase 3: *a requester-style transcript
produces a correctly placed story with acceptance criteria and the review
label.* **PASS.** The story gate filed AGADMIN-10, a story under its epic,
in Backlog with `needs-review` and three Given/When/Then criteria. An epic
split before it filed AGADMIN-6 to AGADMIN-9.

This is a summary. The requests and the items' text are board content, so
they stay out of git. The raw session transcripts are in `transcripts/raw/`,
which is gitignored and kept on the machine that ran them.

## Setup

- **Host:** Claude Code 2.1.152, with the repo loaded as a plugin
  (`claude --plugin-dir <repo>`, [.claude-plugin/plugin.json](../.claude-plugin/plugin.json)).
  Each session started in an empty directory, so the repo's dev `CLAUDE.md`
  was not in context. The global user `CLAUDE.md` was.
- **Framing:** `--append-system-prompt` said the session is a team's backlog
  assistant, that requests are work to file rather than build, and to start
  with the intake skill. Session A below shows why this is needed.
- **Tools:** `describe_board`, `find_items`, `get_item` and `propose_item`
  were pre-allowed, and none of them writes. `commit_item` was left to
  Claude Code's permission prompt, as a second guard on the first live run.
- **Board:** Plane, throwaway project `AGADMIN`, `confirm = "always"`,
  `item_case = "title"`. Token via Bitwarden (the CLAUDE.md live recipe).
- **Requester:** Chris, typing plain requests about a personal weekly
  planning chore, with no slash commands and no tracker terms.

## Findings

| # | Finding | Disposition |
|---|---|---|
| 1 | A plain Claude Code session reads a request as a build task. The skills need the host to say it is a backlog assistant. | The framing line is in the README's Claude Code section. Hermes (Phase 4) and the Agent SDK example need the same line. |
| 2 | Both runs wrote the problem in the third person with the requester's name, while the outcome and criteria said "I". The name came from the global user `CLAUDE.md`, not the conversation. | Fixed in the same PR: intake keeps the requester's voice (I, we, our team) and never adds a name, and the skill examples now match. |
| 3 | In a split, every story repeats the whole request's problem and outcome. | Follow-up: self-contained items for the PO, or shorter stories. Chris's call. |
| 4 | `get_item` and `find_items` show the parent as a bare id, with no key or level. | Follow-up: `expand=parent` returns its `sequence_id` (Phase 1), which makes the key. |
| 5 | `related` becomes a "Related" line in the description, not a board link. The agent said so plainly. | Follow-up: a link is a new write and needs a conformance case (roadmap/14 §8 relations). |
| 6 | Run 1 listed the empty working directory before starting intake. Run 2 went straight to the skill. | None. It was harmless. |
